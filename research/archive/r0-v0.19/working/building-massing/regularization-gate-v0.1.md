# Building Footprint Regularization Gate v0.1

**状态：** provisional / candidate-only；不是生产阈值或最终算法选型。  
**适用范围：** `COV-10`、`COV-20`；与场地级拓扑 `COV-04/05` 和 2D/3D identity `COV-13` 有显式依赖。

## 1. 不可违反的基本契约

1. `TraceGeometry` 永不被规则化覆盖。任何调整生成新的 `ProfessionalFootprintRevision`，保留原对象 ID、Trace revision、参数、差异和回退路径。
2. 正规化结果只是候选；几何有效不等于设计意图正确，IoU 高也不等于拓扑正确。
3. 单体与场地两级验证必须分开：单体轮廓可比较，建筑之间的共享边、邻接、分离、包含、对象数也必须比较。
4. 没有可信尺度/坐标时，只能在图像/本地坐标系中比较；不得把像素偏差伪装成米制容差。
5. 未获确认的高度、层数、typology 不得因生成 3D 的需要被静默补成 confirmed。
6. 设计者明确锁定的几何或关系是 hard invariant。候选与其冲突时拒绝自动应用。

## 2. 结果状态与 Validator verdict 分离

### 设计决策状态

- `preserve_trace`：当前证据不足以证明修改合理，保持 Trace 作为当前权威几何。
- `regularized_candidate`：可提出一个派生候选，但不能自动替换权威几何。
- `needs_review`：意图、拓扑或尺度不确定，需要设计者确认或补充控制信息。

### 校验 verdict

- `pass_candidate_checks`：通过本次声明的几何/拓扑检查；只表示可进入后续审阅，不代表可直接出图。
- `reject_candidate`：违反 hard invariant、输出无效或发生未经授权的对象/拓扑变化。
- `review_required`：差异指标或意图证据尚不足以自动决定。

这两个字段不能合并成一个状态：一个 `regularized_candidate` 仍可能被 Validator 拒绝。

## 3. 自动规则化前的适用性检查

仅在下列证据基本齐备时才生成规则化候选：

- 原始 Trace 已保存且有效；其坐标单位/校准状态明确；
- 存在可解释的规则化意图，例如设计者明确要求“按主要轴线规整”，而不是模型仅凭轮廓像素猜测；
- 主方向估计有置信/稳定性记录，且没有明显多峰方向冲突；
- 已检查曲线边、显著凹槽、院落孔洞、多个 component、意图旋转、斜向翼部和邻接建筑；
- 相关对象的组关系已登记，或明确声明当前候选只做单体预览、不用于场地级更新。

以下情况默认 `preserve_trace` 或 `needs_review`，不得全局正交化：

- 有意旋转的单体与周围主方向不一致；
- 曲线/圆弧轮廓，或多个方向族均具有解释力；
- L/U/院落凹槽、孔洞、复杂凹凸可能是设计意图；
- 两个对象共享边界、紧邻或受同一红线/道路边界约束；
- 尺度不明，或像素/几何误差尚无法映射到项目容差；
- 输入有无效几何、意外 MultiPolygon、退化环或组件数量不明；
- 用户锁定了轮廓、朝向、位置、对象身份或对象间关系。

## 4. 必需的候选差异向量

不建立未经校准的单一总分。每次候选至少输出：

### 单体几何

- `is_valid`、几何类型、component count、hole count；
- IoU（仅作重叠摘要，不作为单独通过条件）；
- 对称差面积与相对面积变化；
- 边界 Hausdorff distance（注明是否 densify 以及坐标单位）；
- 边界点距离分布（至少 P50/P95/P99；真实阈值待数据校准）；
- centroid shift、主方向变化、顶点数变化；
- 最小间隙/净距变化（当附近有道路、红线或其他建筑时）。

### 场地级拓扑

- 对象 ID 与对象数是否保持；
- 原始与候选的 `touches / shared_boundary / overlap / separated / contained_by` 关系差异；
- 共享边长度、间隙宽度、重叠面积；
- 相邻关系图是否发生新增/删除边；
- 锁定关系是否被改变；
- 多表示对象的 footprint revision、body revision 和 stale/rebuild 状态。

## 5. 硬拒绝条件

若无显式批准的设计变更，下列任一项足以拒绝候选自动应用：

- 输出为空、无效或出现未处理的几何类型；
- 已确认的孔洞/院落消失，component 数改变，或两个独立对象合并/一个对象无授权地分裂；
- 已确认的共享边/邻接/分离关系改变；
- 锁定轮廓、位置、朝向、红线关系或对象 ID 被改变；
- 候选超过当前项目已批准的几何偏差容差；
- Body 仍引用旧 Footprint revision，却被报告为 current；
- 高度/单位/坐标系不明却输出看似精确的米制 massing。

“超出容差”只有在容差已有来源和批准记录时才可执行；R0 不虚构通用毫米/百分比阈值。

## 6. 允许成为候选的条件

候选只有在下列条件同时成立时，才可进入设计者审阅：

1. Trace 保留、差异可视化、版本与回退关系可回读；
2. 单体几何合法；
3. component/hole/对象身份与锁定关系不发生未经授权的变化；
4. 场地级拓扑差异已计算；
5. 偏差指标均有单位、参数、方法和适用条件；
6. 不确定项明确暴露，不将候选状态升级为 confirmed；
7. 下游 Body、日照/遮挡和空间冲突检查按依赖关系失效并重跑。

## 7. 阈值校准路线

不先选固定 IoU 或 Hausdorff 阈值。后续用 Tier B/C 的人工配对数据：

1. 对同一草图，由设计者标记“可改的手抖”和“必须保留的意图”；
2. 对候选执行多档参数，记录偏差向量和人工接受/拒绝理由；
3. 按输入类型、比例/分辨率、几何类别和设计阶段分层；
4. 估计可接受候选的误差分布，同时报告危险错误（拓扑/意图损失）；
5. 将项目批准容差作为显式 profile 参数，而不是全局默认常数；
6. 任何新数据、参数、算法版本或设计阶段变化触发相应重验。

## 8. 本版证据边界

- Building Regulariser 官方源码、README、测试和公开 issues 已检查；本地未运行该库（当前环境不能从 PyPI 安装依赖）。
- CartAGen 官方文档提供 FER、矩形变换、递归回归等不同方法；其主要任务背景仍是航空/卫星影像分割得到的建筑物，不能直接视为建筑规划草图的已验证解法。
- `LOCAL-BLDG-002` 仅运行 Shapely 合成候选几何，用来检验 Validator 指标是否能发现人为植入的失败；不证明任何候选算法真实表现。
- 以上是可测试的候选门槛；独立 A1 和真实 Tier B/C 校准尚未完成。
