# 道路语义、Profile 与规则引擎：首轮源码/官方文档分析

**状态：** candidate analysis；不是正式 EVR/AJG，不是架构 DEC。  
**关联：** `COV-21/22/23`、`CAP-ROAD-10..15`、`BEN-ROAD-009..020`。  
**截至：** 2026-10-26。

## 1. 当前最重要的发现

开源生态里没有一个已被本轮证据证明可以直接承担“中国建筑/规划草图 → 设计院级道路设计”的完整工作。已有项目分别覆盖不同层：

1. OSM：道路在路网中的角色/重要性标签；不是法定等级或工程参数。
2. SUMO：道路图、车道、交叉口与车道连接的数据模型；道路类型可提供属性默认值，主要服务交通仿真。
3. Street Generator：类型化的横断面组件模型、确定性渲染和规则检查；当前仓库没有可确认的开源许可证，且它的模型不是完整的平面路线/路网模型。
4. Streetmix：面向共同设计/公众沟通的横断面构成与编辑；其 README 目标不是完整的工程路线几何和规范设计。
5. 中国规范：可以确认若干强制性通用规范的官方发布公告，但当前批次没有成功取得完整条文，不能生成数值参数或合规结论。

因此需要把“道路分类 → 设计 Profile → 路线/节点几何 → 横断面 → 道路面 → CAD/3D 输出”分成独立、可追溯的处理层。

## 2. Street Generator：值得借鉴什么，不能照搬什么

### 已由源码定位支持的观察

- `src/models/street.ts`（blob `e982f8d...`）定义 `ElementType`，包括人行道、骑行道、缓冲带、停车带、机动车道、公交车道、中央分隔、绿化带和两侧建筑等。
- `StreetElement` 核心字段是 `id`、`type`、`side`、`width_m`，并可附带展示样式、建筑楼层和图形元素；`StreetConfig.elements` 是按横断面左右顺序排列的组件集合。
- `src/rules/engine.ts` 将验证分发给 `runRastRules`；规则实现把宽度阈值、相邻组件关系和合计宽度检查写成规则函数，返回 `PASS/WARN/FAIL` 与受影响元素 ID。
- `de_rast_v01_rules.test.ts` 包含边界值、范围上下界、聚合宽度和相邻组件关系的测试。这是值得学习的测试方法。
- GitHub API 仓库元数据 `license=null`，未发现根目录 LICENSE 入口。公开可读不等于已授权复制/集成；许可不清前只做架构研究。

### 主要缺口

当前被检查的模型表示的是**横断面**，不是场地道路的完整几何。它没有表达道路走廊/segment 的拓扑、中心线、交叉口节点、纵断面、高程、坐标基准、适用法域、标准版本、规则出处、分类证据或人工确认状态。规则执行也固定调用一个 RASt 规则模块，没有在已检查的接口中看到按地域/版本解析规则包的机制。

### 可借鉴原则

- 语义组件用受约束的类型，而非自由文本。
- 编辑、渲染、规则检查和导出消费同一份结构化模型。
- 规则输出应定位到对象 ID，便于局部修复。
- 测试必须覆盖边界值、聚合规则和对象间关系。

### 不可借鉴为设计结论的部分

- 不能把 RASt 的阈值复制为中国规则。
- 不能将横断面元素类型直接等同于道路法定等级。
- 不能把 README 所称的“validate”理解成已通过独立工程验证。
- 在许可证明确之前，不将代码纳入依赖或复制源码。

## 3. SUMO 与 OSM：分类和几何模型应拆开

SUMO 的道路网络以节点/交叉口、edge、lane 和 lane connection 表示交通网络；每条 edge 可带车道 shape、速度等属性，连接关系明确记录入口车道如何到达出口车道。它适合作为“网络拓扑与车道语义分离”的数据模型参考，但其目标是交通仿真，不是工程路线设计。官方文档还明确说明：类型映射用于推断缺失的属性，依赖国家/城市上下文；随附映射值是 ad-hoc、尚未验证；交叉口节点合并属于启发式，复杂节点可能误合并。

SUMO edge type file 将道路类型映射到部分默认属性，例如车道数、允许/禁止通行的车辆类别、单行、优先级、速度和可添加的人行道宽度；具体 edge 的显式属性可以覆盖默认值。这个模式可借鉴为“分类/类型 → 参数候选”的机制，但必须增强：

- 每个参数有来源、版本、适用条件和状态；
- 缺失值不得静默变成未经证实的工程默认值；
- `default`、`target`、`minimum`、`maximum`、`mandatory` 语义分开；
- 对冲突标准/冲突约束返回 `needs_review` 或 `infeasible`，而不是挑一个数字继续画。

OSM `highway=*` 可作为网络角色证据，但其文档明确说明，它不保证等同于法定道路分类或物理特征。因此 `highway=residential` 不能直接编译成“中国居住区道路宽度/车道数/设计速度”。

## 4. Streetmix：作为交互与概念设计参考

Streetmix 的 README 将其定位为协作式公共空间/街道断面设计和沟通工具。它适合研究：如何让设计者在横断面上增减人行道、车道、骑行设施、树木与街道家具，并通过可视反馈讨论空间分配。

它不能证明完整的道路平面路线、交叉口扫掠、中心线连续性或中国规范校核已经解决。当前代码 LICENSE 明确为 AGPL-3.0-or-later；若将来考虑复用代码，必须单独评估网络服务义务；内容/素材的许可也需独立确认。

## 5. 中国标准：规则引擎不能只存一张参数表

住建部关于 GB 55011-2021 的公告说明该规范自 2022-01-01 实施、属于强制性工程建设规范，并说明与其不一致的现行工程建设标准规定以该规范为准。GB 55037-2022（建筑防火）与 GB 55019-2021（无障碍）是相关权威来源路线。

本轮仍未取得住建部 GB 55011 官方附件，但一份可访问的二次全文转载列出 CJJ 37-2012（2016版）第 3.4.2、3.4.3、13.3.4 条属于废止的相关强制性条文；其前言同时说明现行标准相关强制性条文由 GB 55011 管辖。这更支持建立逐条关系映射，而不是把整部 CJJ 37 一刀切标成废止。由于原始官方附件访问失败，该条款清单仍须与官方附件复核。GB 55037/GB 55019 的完整条文也未取得。

所以 Profile/Rule 必须保存：`jurisdiction`、`standard_id`、`edition`、`valid_from/to`、`scope`、`applicability`、`clause_locator`、`rule_kind`、`severity`、`conflict_policy`、`verification_status`。未核实的规则不能进入自动 PASS 的强制规则集。

## 6. 候选模型：Road Corridor / Segment / Profile 分离

- **RoadCorridor**：跨越多个几何段仍保持的道路身份和设计意图。
- **RoadSegment**：在路线几何、Profile、用途或约束发生变化处切分；段的边界必须有原因。
- **RoadGraph**：节点、边及连接关系，表达“连接在哪里”，不等同于道路面。
- **Alignment**：中心线的几何元素和控制点，具有 G0/G1/G2 等按需求验证的连续性。
- **CrossSectionProfile**：有序的横断面组件及其宽度/偏移/高程参数。
- **JunctionDesign**：相交道路、交角、转向关系、设计车辆/特殊用途、模板及适用规则。
- **RuleSet**：版本化的规则集合，显式区分硬性要求、项目约束、建议与未知项。
- **Evidence / Change**：分类证据、冲突、人工确认、参数来源和修改前后差异。

`road-profile-schema-v0.1.yaml` 是字段讨论草案，不是最终 CAD-IR schema，也没有填入道路设计数值。
